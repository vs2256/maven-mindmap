StudyMind rebrand — where does “Maven” still live?

Executive Summary

The project was rebranded from a Maven-specific study tool into a generic mind-map tool called StudyMind. The application shell (UI, build script, variable names, branding) has been fully genericized and contains zero Maven references.

However, the shipped sample content — the notes stored in the data files — is still entirely about Maven. Because the header title shown on load comes from that data, and because the notes and git history preserve the original subject, a person browsing the project can still tell it started as a Maven-specific tool.

Can someone tell it was previously Maven-specific?

Yes. Even though the tool code is clean, three things give away the Maven origin to anyone opening or reading the project:

  • The on-load header reads “Maven Interview Mind Map” because meta.title in data/data.json is unchanged.
  • The data files (data/data.json and generated data/data.js) are 100% Maven notes — the root node is literally "Maven".
  • Git history records the rename git mv data/maven.json → data/data.json, and the old filename is recoverable.

A developer reading only index.html or build.py would not know — but the moment they open the app, the README sample notes, or the data files, the Maven origin is obvious.

Category breakdown

Cleared   Tool / branding / build

The application code carries no Maven traces. Header title tab, emblem, footer, PDF report title and filename all say StudyMind, and every global is now APP_META / APP_ROOT / APP_EXPLANATIONS / APP_QUIZZES / APP_GLOSSARY.

Docs   Documentation

README.md describes StudyMind as a generic, any-topic tool and references Maven only to illustrate the example dataset (a plugin snippet, a sample quiz, and a glossary entry). These are intentional teaching examples, not tool branding.

Content   Content / data

This is where nearly all Maven references live (~460 occurrences). It is the sample study material and was intentionally kept. data/data.js is generated from data/data.json by build.py, so the two mirror each other — changing the JSON and rebuilding updates both.

How to fully erase the Maven origin (optional)

If the goal is that no one could tell it was ever Maven-specific, the content and history must also change:

  • Edit meta.title, meta.subtitle, meta.source and the root node text in data/data.json to a neutral subject, then run py build.py to regenerate data/data.js.
  • Replace the Maven sample notes (nodes, explanations, quizzes, glossary) with generic or placeholder content.
  • Update the Maven example references in README.md to a neutral example.
  • Rewrite / squash git history so the maven.json → data.json rename and prior Maven commits are no longer recoverable.

If the current state is acceptable (generic tool + Maven kept as demo content), no action is needed — this report simply documents where things stand.
